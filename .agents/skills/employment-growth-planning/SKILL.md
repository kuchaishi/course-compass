# 就业成长规划

1. 锁定目标岗位、原始 JD 和快照时间。沿用就业模块的资格三态和匹配结果，引用原文。课程记录证明学习接触，作品证据保留核验状态。
2. 按目标覆盖、证据缺口和工时挑选优先技能，结合已有先修与每周可用时间安排两周起步动作。用同一匹配规则模拟新增一份带作品链接、本人确认的成果，保持招聘资格和状态独立。先解释当前不足和对目标的影响，再给项目、交付物和可观察验收条件。
3. 项目按优先技能使用公开技术词查 GitHub。赛事可从用户参考名单和已核对入口选取。A/B 原样作为名单备注，招聘样本的赛事提及和企业合作资料分别展示。缺少招聘依据时可说明能展示的能力。
4. 按同岗位族的招聘原句统计技术主题，列出样本量、要求表述条数和岗位例证，已核对的同一岗位镜像只计一次。优先在岗位族主技术方向内选有证据的主题，使用 Crossref 查可阅读或复现的方法。每轮最多查 GitHub 和 Crossref 各一次。区分没有结果、没有可限范围和来源故障。公开岗位条数和论文数量无法提供招聘人数。
5. 按岗位资格与差距 → 技能 → 动手项目 → 竞赛 → 岗位需求与论文 → 两周行动与验收的顺序反馈。资源链接使用查询结果或已有登记资料。可引用检索结果编号，保持来源和原始链接可追溯。
6. 把采用的项目或与本轮技能匹配的赛事练习接回对应实战任务，保存来源、验收建议、研究时间与岗位快照。赛事练习按普通作品交付与复核，参赛资格由赛务通知决定。首次提交复核材料时固定验收标准。学生选择新技能重点或确认新成果后重算。发现检索或建议问题时，修改项目内的技能查询映射、来源规则或验收模板，更新工作流版本并验证失败回退。

项目页面入口是岗位详情的「成长路线 → 联网成长规划」。公开查询仅使用技术关键词。学生画像采用已有的精简投影，本地模型只收到目标岗位和技能差距等规划摘要。执行与复核接口见项目 README。
